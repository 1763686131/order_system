### 步骤 2：改造订单列表显示逻辑 ✅

**新增的辅助函数**（共 12 个）：

| 函数名 | 功能 | 说明 |
|--------|------|------|
| `getContactPerson()` | 获取联系人 | 优先 `contact_person` → 回退 `receiver_name` |
| `getContactPhone()` | 获取联系电话 | 优先 `contact_phone` → 回退 `receiver_phone` |
| `getContactAddress()` | 获取联系地址 | 优先 `contact_address` → 回退 `receiver_address` |
| `getGoodsDisplay()` | 获取商品信息显示 | 新订单显示"商品名 等N件"，旧订单显示 `goods_name` |
| `getGoodsTooltip()` | 获取商品悬停提示 | 新订单显示完整明细，旧订单显示原文 |
| `getTotalWeight()` | 获取总重量 | 新订单汇总 `order_goods`，旧订单读取 `goods_weight` |
| `getPackageCount()` | 获取件数 | 新订单汇总 `packages`，旧订单读取 `goods_quantity` |
| `getShouldReceive()` | 获取应收金额 | 优先 `should_receive` → 回退 `total_amount` |
| `getCurrentPayment()` | 获取已收金额 | 读取 `current_payment` |
| `getCurrentDebt()` | 获取未收金额 | 优先 `current_debt`，否则计算差额 |
| `isNewOrder()` | 判断是否为新订单 | 检查 `order_goods` 是否存在 |
| `showOrderDetail()` | 显示商品明细弹窗 | 打开商品明细弹窗 |

**模板改造**：
- ✅ 联系人列：使用 `getContactPerson(order)`
- ✅ 联系电话列：使用 `getContactPhone(order)`
- ✅ 联系地址列：使用 `getContactAddress(order)`
- ✅ 商品列：使用 `getGoodsDisplay(order)`，新订单显示 📋 按钮
- ✅ 重量列：使用 `getTotalWeight(order)`
- ✅ 应收金额列：使用 `getShouldReceive(order)`
- ✅ 已收金额列：使用 `getCurrentPayment(order)`
- ✅ 未收金额列：使用 `getCurrentDebt(order)`

## 📝 主要特性

### 1️⃣ 智能字段识别

**自动判断订单类型**：
- 检测 `order.order_goods` 是否存在
- 新订单显示 📋 按钮，旧订单显示 ▼ 按钮
- 不同类型使用不同的数据获取逻辑

### 2️⃣ 商品明细弹窗

**触发方式**：
- 点击新订单商品列的 📋 图标
- 仅对新订单（有 `order_goods`）生效

**显示内容**：
- 订单基本信息（4 项）
- 商品明细表格（完整的 10 列）
- 财务汇总信息（8 项）

**设计亮点**：
- 宽度自适应（90%，最大 1200px）
- 内容可滚动（最大高度 85vh）
- 表格美观（边框、斑马纹、悬停效果）
- 重点突出（应收、欠款加粗显示）

### 3️⃣ 增强搜索

**搜索范围扩大**：
- 旧字段：订单ID、客户、联系人、单号
- 新字段：订单编号、工程项目、联系地址
- 商品明细：支持搜索商品明细中的任意商品

**搜索体验**：
- 模糊匹配，不区分大小写
- 实时过滤，即时反馈
- 新旧订单都能搜索到

### 4️⃣ 财务金额显示

**改造前**：
- 应收金额：`-`
- 已收金额：`-`
- 未收金额：`-`

**改造后**：
- 应收金额：`¥2542.50`（读取 `should_receive`）
- 已收金额：`¥2542.50`（读取 `current_payment`）
- 未收金额：`¥0.00`（读取 `current_debt` 或计算）

**兼容性**：
- 新订单显示实际金额
- 旧订单显示 `-`（因为没有这些字段）
