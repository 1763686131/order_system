## ✨ 核心功能实现

### 1. 新旧字段并存 ✅

**实现方式**：保存订单时同时填充新旧两套字段

```javascript
// 新字段
{
  "customer_id": 1,
  "order_number": "ZG20260904001",
  "order_goods": [...],
  "subtotal_amount": 1000.00
}

// 旧字段（自动映射）
{
  "order_client": "锦州森源",
  "goods_name": "碳纤维胶 5kg x10、灌注胶 10kg x5",
  "goods_weight": "15kg",
  "goods_quantity": "3件"
}
```

### 2. 库存扣减 ✅

**实现逻辑**：
1. 保存前检查所有商品库存
2. 任何一个商品库存不足，整个订单不保存
3. 全部检查通过后，统一扣减库存
4. 使用线程锁保证并发安全

**示例**：
```python
# 检查
for item in items:
    if product['stock'] < item['quantity']:
        return error("库存不足")

# 扣减
for item in items:
    product['stock'] -= item['quantity']
```

### 3. 财务计算 ✅

**自动计算字段**：
- 小计 = Σ(数量 × 单价)
- 税额 = Σ(含税金额 - 不含税金额)
- 价税合计 = 小计 + 税额
- 本单应收 = 折扣金额 + 其他费用
- 本单欠款 = 本单应收 - 本次收款

### 4. 表单校验 ✅

**校验规则**：
- 门店、客户、仓库必选
- 联系人、联系方式必填
- 至少一条商品明细
- 商品的件数、数量、单价必填且大于0

### 5. 订单编号生成 ✅

**格式**：`ZG + YYYYMMDD + 三位ID`

**示例**：
- ID=1 → ZG20260904001
- ID=123 → ZG20260904123

### 6. 错误处理 ✅

**处理场景**：
- 网络错误
- 库存不足（显示商品名称和当前库存）
- 表单校验失败
- 商品不存在
- 客户不存在
- 重复提交（按钮禁用）

## 🎯 关键技术决策

### 1. 渐进式重构策略

**决策**：新旧格式并存，而不是一次性替换

**理由**：
- ✅ 不影响现有业务
- ✅ 降低风险
- ✅ 可以逐步迁移
- ✅ 易于回滚

### 2. 旧字段作为冗余

**决策**：保留旧字段，从新字段自动映射

**理由**：
- ✅ 旧页面无需修改即可查看新订单
- ✅ 简化查询逻辑
- ✅ 提高兼容性

### 3. 库存实时扣减

**决策**：保存订单时同步扣减库存

**理由**：
- ✅ 保证数据一致性
- ✅ 避免超卖
- ✅ 简化业务逻辑

### 4. 使用线程锁

**决策**：使用 `orders_lock` 保护订单保存操作

**理由**：
- ✅ 防止并发写入冲突
- ✅ 保证库存扣减准确
- ✅ 保证订单ID连续

### 5. 前端表单校验

**决策**：在前端进行完整的表单校验

**理由**：
- ✅ 提升用户体验（即时反馈）
- ✅ 减少无效请求
- ✅ 减轻后端压力

## ⚠️ 风险与限制

### 当前限制

1. **旧页面未改造**
   - 订单列表页面只能显示旧字段
   - 订单详情页面无法显示商品明细
   - 订单编辑功能不支持新格式

2. **数据冗余**
   - 新旧字段并存增加了数据量
   - 需要维护两套字段的一致性

3. **性能考虑**
   - 保存时需要查询多个数据源
   - 文件读写频繁可能影响性能

### 风险缓解

1. **数据备份**
   - 建议测试前备份数据文件
   - 使用临时文件写入 + 原子替换

2. **回滚方案**
   - 保留了旧格式订单的创建逻辑
   - 可以随时切换回旧版本

3. **性能优化**
   - 使用线程锁减少并发冲突
   - 后续可考虑引入数据库
