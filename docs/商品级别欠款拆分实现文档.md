# 商品级别欠款拆分实现文档

## 概述

本文档描述了欠款明细表中商品级别欠款拆分的业务逻辑和计算规则，用于指导后端API实现。

## 业务场景

在欠款明细表中，一条业务记录（如销售订单）可能包含多个商品。为了更精细地追踪欠款，需要将该记录的欠款变动按商品明细进行拆分，并计算每个商品级别的累计欠款。

### 示例数据

**订单记录**：
- 订单编号：SO20260910001
- 订单日期：2026-09-10
- 应收金额：2542.50元
- 已收金额：1000元
- **本单欠款变动**：+1542.50元

**订单商品明细**：
1. 碳纤维胶：数量10桶，单价100元，小计1000元
2. 环氧树脂：数量25桶，单价50元，小计1250元
3. **商品总金额**：2250元

## 核心计算逻辑

### 1. 商品欠款分摊计算

**分摊原则**：按商品金额占总金额的比例分摊本单的欠款变动。

**计算公式**：
```
商品分摊欠款 = (商品小计 / 所有商品总额) × 本单欠款变动
```

**代码实现示例（JavaScript）**：
```javascript
function calculateProductDebt(record, productIndex) {
  const products = record.products
  
  // 计算商品总金额
  const totalAmount = products.reduce((sum, p) => {
    return sum + (p.quantity || 1) * (p.price || 0)
  }, 0)
  
  // 如果总金额为0，平均分摊
  if (totalAmount === 0) {
    return record.debtAmount / products.length
  }
  
  // 当前商品小计
  const product = products[productIndex]
  const productAmount = (product.quantity || 1) * (product.price || 0)
  
  // 按比例分摊
  return (productAmount / totalAmount) * record.debtAmount
}
```

**示例计算**：
- 碳纤维胶分摊：(1000 / 2250) × 1542.50 = 685.56元
- 环氧树脂分摊：(1250 / 2250) × 1542.50 = 856.94元
- **验证**：685.56 + 856.94 = 1542.50 ✓

### 2. 商品级别累计欠款计算

**计算原则**：
1. 从期初欠款开始
2. 按业务日期时间顺序累加每条记录的欠款变动
3. 对于有多个商品的记录，按商品顺序依次累加各自的分摊欠款

**计算步骤**：

**步骤1：对所有记录按时间排序**
```javascript
const sortedRecords = records.sort((a, b) => {
  const dateA = new Date(a.businessDate)
  const dateB = new Date(b.businessDate)
  return dateA - dateB
})
```

**步骤2：累计计算到目标商品行**
```javascript
function calculateProductCurrentDebt(records, targetRecordId, targetProductIndex) {
  let cumulative = initialDebt  // 期初欠款
  
  // 按时间排序
  const sorted = records.sort((a, b) => 
    new Date(a.businessDate) - new Date(b.businessDate)
  )
  
  for (const record of sorted) {
    if (record.id === targetRecordId) {
      // 到达目标记录，累加到目标商品
      for (let i = 0; i <= targetProductIndex; i++) {
        cumulative += calculateProductDebt(record, i)
      }
      break
    } else {
      // 其他记录，累加全部欠款变动
      cumulative += record.debtAmount
    }
  }
  
  return cumulative
}
```

**示例计算**：

假设有以下时间顺序的记录：

| 日期 | 业务类型 | 商品 | 欠款变动 | 累计欠款 |
|------|---------|------|---------|---------|
| 初始 | - | - | - | 5000.00 |
| 09-01 | 订单A | 单商品 | +2000.00 | 7000.00 |
| 09-10 | 订单B | 商品1 (分摊+685.56) | - | 7685.56 |
| 09-10 | 订单B | 商品2 (分摊+856.94) | - | 8542.50 |
| 09-15 | 收款 | - | -3000.00 | 5542.50 |

### 3. 特殊情况处理

#### 3.1 商品总金额为0的情况
```javascript
if (totalAmount === 0) {
  // 平均分摊欠款
  return record.debtAmount / record.products.length
}
```

#### 3.2 负欠款（收款/退货）
- 负欠款同样按比例分摊
- 累计欠款可能减少

#### 3.3 单商品记录
- 直接使用记录的欠款变动，不需要拆分
- 累计欠款正常计算

### 计算要求

1. **精度要求**：
   - 金额保留2位小数
   - 分摊计算使用高精度decimal类型
   - 最后一个商品的分摊金额 = 总欠款 - 前面所有商品分摊金额之和（避免尾差）

2. **排序要求**：
   - 记录按 `businessDate` 升序排列
   - 相同日期按 `id` 升序排列

3. **性能优化**：
   - 支持分页查询
   - 累计欠款可以在单次查询中计算
   - 考虑使用窗口函数优化SQL查询

### SQL实现示例（PostgreSQL/MySQL）

```sql
-- 计算商品级别分摊欠款和累计欠款
WITH OrderedRecords AS (
  SELECT 
    dr.*,
    ROW_NUMBER() OVER (ORDER BY dr.business_date, dr.id) as rn
  FROM debt_records dr
  WHERE dr.customer_id = :customerId
),
ProductAllocations AS (
  SELECT 
    dr.id as record_id,
    dr.business_date,
    dr.debt_amount,
    p.product_id,
    p.name,
    p.quantity,
    p.price,
    p.quantity * p.price as product_subtotal,
    SUM(p.quantity * p.price) OVER (PARTITION BY dr.id) as record_total,
    -- 商品分摊欠款
    CASE 
      WHEN SUM(p.quantity * p.price) OVER (PARTITION BY dr.id) > 0
      THEN (p.quantity * p.price) / SUM(p.quantity * p.price) OVER (PARTITION BY dr.id) * dr.debt_amount
      ELSE dr.debt_amount / COUNT(*) OVER (PARTITION BY dr.id)
    END as allocated_debt,
    ROW_NUMBER() OVER (PARTITION BY dr.id ORDER BY p.line_no) as product_seq
  FROM debt_records dr
  JOIN debt_record_products p ON p.record_id = dr.id
  WHERE dr.customer_id = :customerId
)
SELECT 
  *,
  -- 累计欠款：期初 + 之前所有记录的欠款变动 + 当前记录中当前商品及之前的分摊
  :initialDebt 
  + SUM(debt_amount) OVER (ORDER BY business_date, record_id ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING)
  + SUM(allocated_debt) OVER (PARTITION BY record_id ORDER BY product_seq) as cumulative_debt
FROM ProductAllocations
ORDER BY business_date, record_id, product_seq;
```

## 注意事项

1. **浮点数精度**：使用decimal类型，避免浮点数计算误差
2. **尾差处理**：最后一个商品的分摊金额通过差值计算，确保总和一致
3. **排序稳定性**：相同时间的记录使用ID作为次要排序字段
4. **性能考虑**：大量数据时考虑分页和索引优化
5. **边界情况**：商品金额为0、负欠款、单商品等情况的处理
