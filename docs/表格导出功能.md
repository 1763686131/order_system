# 表格导出功能

本文整理项目现有的表格导出实现，供其它页面接入时复用。代码核对日期：2026-10-14。

## 实现与入口

项目使用本地依赖 `xlsx`（`package.json` 声明 `^0.18.5`，当前安装版本为 `0.18.5`），也有手动生成 CSV 和下载后端 CSV 的实现。无需引入在线 CDN。

| 方式 | 适用场景 | 参考代码 |
| --- | --- | --- |
| 共用 Excel 工具 | 固定列顺序、列宽、行高、标题和合并单元格 | [excelExport.js](../src/utils/excelExport.js) 的 `exportToExcel` |
| 直接使用 `xlsx` | 对象数组转换为工作表，或需要直接操作单元格、工作簿 | [PaymentHistory.vue](../src/views/admin/finance/PaymentHistory.vue) 的 `exportExcel`、[StockRecordList.vue](../src/views/admin/products/StockRecordList.vue) 的 `exportExcel` |
| 前端生成 CSV | 只需导出明细文本，不需要多个工作表和合并单元格 | [InventoryList.vue](../src/views/admin/products/InventoryList.vue) 的 `handleExport`、[PartyList.vue](../src/components/admin/PartyList.vue) 的 `handleExport` |
| 后端返回文件 | 后端统一筛选、检查权限并生成下载内容 | [AccountManage.vue](../src/views/admin/hr/AccountManage.vue) 的 `exportPreview`、[employees.py](../backend/routes/employees.py) |

Excel 导出的基本流程：

```text
取得业务数据 → 应用筛选/确定导出范围 → 按导出列整理数据
→ 生成工作表 → 添加到工作簿 → XLSX.writeFile 触发浏览器下载
```

共用工具只负责生成文件，不读取页面表格 DOM，也不自动获取接口数据、应用筛选、处理分页或检查权限。新页面需要自行完成这些步骤。

## 推荐接入方式

在 Vue 页面的 `<script setup>` 中导入共用工具，按页面业务字段调整下面的列配置。示例字段为 `documentNo`、`customerName`、`phone`、`totalAmount` 和 `remark`。

```js
import { exportToExcel } from '@/utils/excelExport'

function exportRecords(records) {
  if (!Array.isArray(records) || records.length === 0) return false

  const toNumber = value => {
    const number = Number(value)
    return Number.isFinite(number) ? number : 0
  }
  const columns = [
    { title: '单据编号', width: 22, value: row => String(row.documentNo ?? '') },
    { title: '客户', width: 18, value: row => row.customerName ?? '' },
    { title: '电话', width: 18, value: row => String(row.phone ?? '') },
    { title: '金额', width: 14, value: row => toNumber(row.totalAmount) },
    { title: '备注', width: 30, value: row => row.remark ?? '' }
  ]
  const now = new Date()
  const date = [
    now.getFullYear(),
    String(now.getMonth() + 1).padStart(2, '0'),
    String(now.getDate()).padStart(2, '0')
  ].join('-')

  exportToExcel({
    filename: `业务记录-${date}`,
    sheetName: '业务记录',
    data: [
      columns.map(column => column.title),
      ...records.map(record => columns.map(column => column.value(record)))
    ],
    colWidths: columns.map(column => ({ wch: column.width }))
  })
  return true
}
```

页面已存在 `filteredRecords` 计算属性时，按钮可以绑定 `@click="exportRecords(filteredRecords)"`；Vue 模板会自动解包 ref。在脚本中调用则使用 `exportRecords(filteredRecords.value)`。空数据返回 `false`，页面可用现有提示组件说明“暂无可导出数据”。

按钮的禁用、导出权限和异常提示由页面负责；不要仅因按钮可见就跳过处理函数中的权限检查。

### `exportToExcel` 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `filename` | `'导出文件'` | 不含扩展名，工具会追加 `.xlsx` |
| `sheetName` | `'Sheet1'` | 工作表名称 |
| `data` | `[]` | 二维数组，通常第一行是表头，之后是明细 |
| `colWidths` | `[]` | 按列顺序设置，例如 `[{ wch: 20 }, { wch: 12 }]`，宽度按字符数估算 |
| `rowHeights` | `[]` | 按行顺序设置，例如 `[{ hpt: 30 }]`，高度单位为磅 |
| `merges` | `[]` | 合并区域，例如 `[{ s: { r: 0, c: 0 }, e: { r: 0, c: 3 } }]` |
| `styles` | `{}` | 现有行样式配置，限制见下文 |

行列索引均从 `0` 开始。文件名使用业务名称时应处理 `/ \ : * ? " < > |` 等非法字符；工作表名称不要超过 31 个字符，也不要包含 `: \ / ? * [ ]`。

### 标题、合并单元格和汇总

下面的四列表格可以直接使用；实际页面应传入业务已有的汇总数值。

```js
import { exportToExcel } from '@/utils/excelExport'

function exportSummary(records, totalAmount) {
  const data = [
    ['业务记录汇总'],
    ['单据编号', '客户', '金额', '备注'],
    ...records.map(row => [
      String(row.documentNo ?? ''),
      row.customerName ?? '',
      Number(row.totalAmount) || 0,
      row.remark ?? ''
    ]),
    ['合计', '', totalAmount, '']
  ]

  exportToExcel({
    filename: '业务记录汇总',
    sheetName: '汇总',
    data,
    colWidths: [{ wch: 22 }, { wch: 18 }, { wch: 14 }, { wch: 30 }],
    rowHeights: [{ hpt: 30 }],
    merges: [{ s: { r: 0, c: 0 }, e: { r: 0, c: 3 } }]
  })
}
```

工具还导出了 `TITLE_STYLE`、`HEADER_STYLE`、`DATA_STYLE`、`SUMMARY_STYLE`。`styles` 接受 `titleRow`、`headerRow`、`dataRowStart`、`summaryRow` 及对应的 `titleStyle`、`headerStyle`、`dataStyle`、`summaryStyle`。

**现有样式限制：**工具把样式对象赋给单元格的 `.s`，并传入 `cellStyles: true`，但本项目当前安装的 `xlsx 0.18.5` 没有把这些自定义字体、填充色和边框写入生成的文件。本地写入并回读工作簿已验证这一点；数值、列宽、行高仍可保存。不要将这些常量当作已经实现的文件样式能力；有样式要求时，需要另行实现并验证。

此外，现有 `dataStyle` 的行范围会排除最后一行，适合最后一行为汇总的布局；传入 `styles` 时还应保证 `data` 至少包含有效表头，避免对空工作表读取 `!ref` 失败。

## 直接使用 `xlsx`

对象数组可通过 `json_to_sheet` 转换。明确指定 `header`，可以固定列顺序。需要更多工作表时，多次调用 `book_append_sheet`，使用不同的工作表名称。

```js
import * as XLSX from 'xlsx'

function exportSimpleRecords(records) {
  const rows = records.map(row => ({
    单据编号: String(row.documentNo ?? ''),
    客户: row.customerName ?? '',
    金额: Number(row.totalAmount) || 0
  }))
  const worksheet = XLSX.utils.json_to_sheet(rows, {
    header: ['单据编号', '客户', '金额']
  })
  worksheet['!cols'] = [{ wch: 22 }, { wch: 18 }, { wch: 14 }]
  const workbook = XLSX.utils.book_new()
  XLSX.utils.book_append_sheet(workbook, worksheet, '业务记录')
  XLSX.writeFile(workbook, '业务记录.xlsx')
}
```

`PaymentHistory.vue` 导出 `filteredReceipts.value`；`StockRecordList.vue` 导出 `filteredRecords.value`。这两个入口均使用筛选结果，而非页面的分页切片。

### 销售订单与物流订单

[UnifiedOrderList.vue](../src/views/admin/sales/UnifiedOrderList.vue) 的 `handleExport` 已接入 `exportToExcel`，导出当前账号可访问的全部 `filteredOrders.value`，沿用关键词、门店、状态、日期、物流发货方式筛选和当前排序，覆盖所有分页。勾选记录用于页面已有操作，不改变导出范围。

例如日期筛选后剩余 65 条订单，每页显示 30 条，无论当前在第几页，文件都包含这 65 条，不包含日期范围外的订单。修改筛选条件或点击“查询”会回到第一页，导出成功后提示当前筛选结果的实际条数。

销售模式导出订单编号、日期、客户、收货人、电话、地址、货物、应收金额、已收金额、未收金额、状态和备注；物流模式使用对应的重量、发货方式、单号、回单和运费列。地址、备注和全部商品明细保留完整内容，不使用页面截断文字。

金额保存为数值，保留零值；已收金额包含 `current_payment` 和 `balance_applied`，未收金额优先使用 `current_debt`，缺失时按应收减已收计算。销售模式沿用 `admin.sales.order.export` 权限检查；数据加载期间禁止导出，空结果和导出失败使用页面现有通知提示。文件名为 `销售订单-本地日期.xlsx` 或 `物流订单-本地日期.xlsx`。

## CSV 导出

CSV 是文本文件，与 `.xlsx` 的能力不同。不要只修改扩展名来转换格式。现有客户/供应商档案、库存档案和客户欠款详情均有前端 CSV 实现。

下面的通用示例包含 UTF-8 BOM，处理单元格中的逗号、双引号和换行，并在下载后释放对象 URL：

```js
function downloadCsv(filename, rows) {
  const escapeCell = value => `"${String(value ?? '').replace(/"/g, '""')}"`
  const csv = rows.map(row => row.map(escapeCell).join(',')).join('\r\n')
  const blob = new Blob(['\uFEFF', csv], { type: 'text/csv;charset=utf-8;' })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = `${filename}.csv`
  document.body.appendChild(link)
  link.click()
  link.remove()
  URL.revokeObjectURL(url)
}
```

调用示例：`downloadCsv('业务记录', [['单据编号', '金额'], ['0000123', 0]])`。CSV 中带前导零的编码、长号码在 Excel 打开时可能被自动转换；需要保留这类字段时，优先生成 `.xlsx`，并向工作表传入字符串。

## 服务端数据与下载

### 员工档案：后端生成 CSV

`AccountManage.vue` 的 `exportPreview` 将当前关键词、部门、在职状态和账号状态传给 `GET /api/admin/employees/export`。后端读取符合条件的员工，生成带 UTF-8 BOM 的 CSV；前端以 Blob 下载为 `员工档案.csv`。

可复用的请求形式如下。`params` 由调用页面传入，例如 `{ keyword, departmentId, employmentStatus, accountStatus }`。

```js
import request from '@/api/request'

async function downloadEmployeeCsv(params) {
  const blob = await request({
    url: '/admin/employees/export',
    method: 'GET',
    params,
    responseType: 'blob'
  })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = '员工档案.csv'
  document.body.appendChild(link)
  link.click()
  link.remove()
  URL.revokeObjectURL(url)
}
```

[request.js](../src/api/request.js) 已配置 `/api` 前缀，成功响应拦截器直接返回 `response.data`，因此这里拿到的是 Blob，不要再读取 `blob.data`。页面处理权限、请求中状态和失败提示；员工导出接口也检查员工详情权限。

### 供应商欠款详情：先取全量 JSON，再生成 Excel

[DebtDetails.vue](../src/views/admin/finance/DebtDetails.vue) 的供应商模式调用 `GET /api/suppliers/:id/debt-details`，保留当前筛选条件并增加 `export=1`。

该参数由 [supplier_finance.py](../backend/routes/supplier_finance.py) 专门处理：检查 `admin.finance.supplier_statement.export` 权限，返回符合筛选的全量明细，跳过普通分页。响应仍是 JSON；前端添加期初余额、明细和期末余额后，调用 `xlsx` 生成文件。

`export=1` 不是所有接口都支持的通用开关。其它采用服务端分页的页面，需要先确认接口是否提供全量导出能力。

## 运费记录专用函数

`excelExport.js` 还提供 `exportFreightRecords(params)`，调用示例见 [LogisticsTruckReconciliation.vue](../src/views/admin/finance/LogisticsTruckReconciliation.vue) 的 `exportData`。

该函数固定生成运费记录的 13 列，包含标题、日期、订单多笔运费、备用金和汇总，不适合作为任意列表的默认模板。

| 参数 | 说明 |
| --- | --- |
| `periodText` | 日期范围文字，用于标题内容和文件名 |
| `mergedData` | 包含 `itemType: 'order'` 或 `'fund'` 的合并行数据 |
| `totalFreight`、`finalBalance` | 运费合计、备用金余额，均为数值 |
| `getDisplayIndex`、`formatDate` | 序号和日期处理函数 |
| `getGoodsName`、`getTotalWeight` | 货物名称、重量处理函数 |
| `getChannelName`、`getLogisticsNumber` | 渠道、车牌号/单号处理函数 |
| `getFreightAmountForRow`、`getPaidAmount` | 当前行运费和已支付金额处理函数 |
| `calculateBalance`、`hasReceipt` | 按合并行索引计算余额、判断回单的函数 |

目前调用方的 `mergedOrdersAndFunds` 由**当前分页的订单**与**当前期间备用金**合并而成。不能据此认为导出涵盖全部筛选订单；需要全量导出时，应同时核对合并数据、余额计算和汇总的范围。

## 新页面复用时的约定

1. 先明确导出全部筛选结果、当前页还是勾选记录；按钮不会自动决定范围。服务端分页时，前端当前持有的数据通常不足以代表全部记录。
2. 金额和数量保留原始数值，零值导出为 `0`。欠款详情页面中显示的 `-` 只是展示规则，不应替换导出的真实零值。财务汇总沿用业务已有计算结果。
3. 单号、电话和编码使用字符串；导出字段、列顺序、状态文字、日期格式由业务页明确配置，不依赖 HTML 显示内容。
4. 文件名中的本地日期可参考推荐示例；`toISOString().slice(0, 10)` 使用 UTC 日期，可能与本地日期不同。
5. 涉及权限时同时处理按钮和导出函数；如果调用后端接口，后端也需验证权限和数据范围。销售订单使用 `admin.sales.order.export`，供应商对账使用 `admin.finance.supplier_statement.export`；不要机械套用到其它业务。
6. 页面拖动后的列宽不会自动带入文件；导出列宽由 `colWidths` 或工作表 `!cols` 单独定义。目前没有共用的导出列选择弹窗。
