# 表格列顺序与显示隐藏

列顺序、显示隐藏与列宽统一封装到 `v-table-layout`。普通表格直接使用统一指令即可，完整覆盖页面和合并单元格说明见 [表格布局调整](./表格布局调整.md)；本文说明显示开关和需要自行管理列数组时的低层 API。

## 显示隐藏开关

双击表头，打开“调整表格列”窗口。每列右侧有“显示 / 隐藏”开关：

- 关闭开关，再点击“应用设置”，该列的标题、正文、对应合计和列宽空间一起移除。
- 隐藏列仍在设置窗口中保留；重新打开开关并应用，即可恢复到保存的排序位置。
- 隐藏状态、列顺序和列宽分别保存，刷新页面后恢复，各表格和业务模式互不覆盖。
- 开关和排序都只修改草稿；取消、关闭、Esc 或点击遮罩不影响当前表格。
- “恢复默认”同时恢复默认顺序和全部显示，仍需点击“应用设置”。
- 至少保留一列；最后一列的关闭开关禁用。固定位置不等于必须显示，固定列也可隐藏。
- 业务上必须显示的列，可在 `<th>` 或 `<col>` 设置 `data-column-hideable="false"`；其开关禁用。

隐藏只改变当前浏览器的显示偏好，不删除业务数据，不修改业务计算和 Excel 导出的原有字段。

## 已接入页面

所有已使用 `v-table-layout` 的表格均支持显示开关，包括财务订单、物流订单、采购列表、录单明细、库存、往来单位和财务对账等表格。

- 双击表头文字或表头空白处，打开“调整表格列”窗口。
- 键盘聚焦表头区域后，按 Enter 或空格也可以打开窗口。
- 按住列名前的拖动图标上下移动，支持鼠标和触屏；上下箭头按钮也可以移动一列。
- 拖动图标获得键盘焦点后，按上下方向键调整位置。
- 点击“应用设置”后，表头、数据单元格、`colgroup` 列宽同步更新。
- “恢复默认”只重置窗口中的草稿，仍需点击“应用设置”；取消、关闭或 Esc 不修改表格。
- 多选列固定在最左侧，已有吸附操作列固定在最右侧；其它列可以移动。
- 财务和物流列表分别保存顺序，刷新页面后恢复；设置仅保存在当前浏览器，不修改接口或订单数据。
- 原有日期排序、复选框、行操作、权限判断和列宽拖动保持有效。双击列宽调整边界仍恢复列宽，不打开排序窗口。

统一指令现已覆盖所有原有列宽调整表格，包括订单详情商品明细。移动端订单卡片保持原有交互，Excel 导出继续采用原有业务列顺序。

## 可复用模块

| 文件 | 职责 |
| --- | --- |
| `src/composables/useTableColumnOrder.js` | 排序状态、可见列、隐藏标识、保存/读取浏览器偏好、处理列的增减 |
| `src/components/common/TableColumnOrderDialog.vue` | 排序草稿、显示开关、上下移动、恢复默认、确认/取消和键盘焦点 |

使用低层 composable 时，列顺序由 Vue 数据驱动；统一指令则负责节点布局和 Vue 更新前的还原。两种方式不要同时管理同一张表的顺序。

## 其它表格接入示例

```vue
<script setup>
import { computed, ref } from 'vue'
import { useTableColumnOrder } from '@/composables/useTableColumnOrder'
import TableColumnOrderDialog from '@/components/common/TableColumnOrderDialog.vue'

const records = ref([])
const tableColumns = computed(() => [
  { key: 'name', label: '商品名称', width: 160 },
  { key: 'code', label: '商品编码', width: 120 },
  { key: 'stock', label: '库存', width: 100 },
  { key: 'actions', label: '操作', width: 100, fixed: 'end' }
])
const {
  orderedColumns,
  visibleColumns,
  hiddenColumnKeys,
  columnOrderVisible,
  openColumnOrder,
  applyColumnOrder
} = useTableColumnOrder(tableColumns, { storageKey: 'product-list' })
</script>

<template>
  <TableColumnOrderDialog
    v-model:visible="columnOrderVisible"
    :columns="orderedColumns"
    :default-columns="tableColumns"
    :hidden-keys="hiddenColumnKeys"
    @apply="applyColumnOrder"
  />

  <div class="table-scroll">
    <table v-table-layout="{ storageKey: 'product-list', resizeMode: 'fit', reorder: false }">
      <colgroup>
        <col
          v-for="column in visibleColumns"
          :key="column.key"
          :data-column-key="column.key"
          :style="{ width: `${column.width}px` }"
        />
      </colgroup>
      <thead title="双击调整列顺序和显示" @dblclick.stop.prevent="openColumnOrder">
        <tr>
          <th
            v-for="column in visibleColumns"
            :key="column.key"
            :data-column-key="column.key"
          >{{ column.label }}</th>
        </tr>
      </thead>
      <tbody>
        <tr v-for="record in records" :key="record.id">
          <td v-for="column in visibleColumns" :key="column.key">
            <button v-if="column.key === 'actions'" type="button">查看</button>
            <template v-else>{{ record[column.key] }}</template>
          </td>
        </tr>
        <tr v-if="!records.length">
          <td :colspan="visibleColumns.length">暂无数据</td>
        </tr>
      </tbody>
    </table>
  </div>
</template>

<style scoped>
.table-scroll { overflow-x: auto; }
table { width: 100%; table-layout: fixed; border-collapse: collapse; }
</style>
```

业务列中的按钮、金额格式化、提示、状态标签等仍由业务页面渲染。弹窗接收包含隐藏列的 `orderedColumns`，表格的 `colgroup`、表头和每个数据行遍历 `visibleColumns`；否则隐藏的列会继续显示，或无法在弹窗中重新打开。

## 列定义

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `key` | 是 | 唯一且稳定的字符串标识，用于排序、Vue `key` 和列宽匹配；不要使用显示序号 |
| `label` | 是 | 弹窗中的列名称 |
| `fixed` | 否 | `'start'` 固定在最左侧；`'end'` 固定在最右侧；省略时允许移动 |
| `hideable` | 否 | 默认 `true`；`false` 表示必须显示，开关不可关闭 |
| 其它字段 | 否 | 原样保留；如 `width`、`minWidth`、`headerClass`、`resizable`，由业务模板绑定 |

不要通过 `nth-child()` 指定随列移动的宽度或业务样式，改用列的 class 或 `[data-column-key="..."]`。

固定列只影响排序位置；是否允许调整宽度由 `v-table-layout` 的 `data-resizable` 决定，是否允许隐藏由 `hideable` 决定，三者相互独立。

## Composable API

```js
useTableColumnOrder(columns, { storageKey })
```

- `columns`：列定义数组或其 `ref` / `computed`，按默认顺序提供当前权限和业务模式下的全部列，包含用户主动隐藏的列。
- `storageKey`：字符串或其 `ref` / `computed`；不同表格、业务模式使用独立标识。省略时顺序与显示偏好仅保留在当前组件内。
- `orderedColumns`：排序后的全部当前业务列，包含用户关闭显示的列，供设置窗口使用。
- `visibleColumns`：排序并过滤隐藏列后的数组，供表格渲染。
- `hiddenColumnKeys`：当前业务列中被隐藏的 key 数组。
- `columnOrderVisible`：弹窗可见状态。
- `openColumnOrder(event?)`：打开弹窗；自动忽略来自列宽拖动边界、复选框或下拉框的双击。
- `applyColumnOrder(keys, hiddenKeys?)`：同时应用排序和隐藏列，保存偏好并关闭弹窗；省略第二个参数时保留当前隐藏设置，兼容旧调用。
- `normalizeColumnOrder(columns, keys?)`：独立导出的纯函数，去重、忽略未知 key、补入新增列并保持固定列位置。
- `normalizeHiddenColumnKeys(columns, keys?)`：规范化隐藏列表，过滤无效 key 和不可隐藏列，并至少保留一列显示。

`TableColumnOrderDialog` 接收 `visible`、`columns`、`defaultColumns`、可选的 `hiddenKeys`（默认 `[]`）和 `title`，发出 `update:visible` 与 `apply(keys, hiddenKeys)` 事件。第一参数仍是原有排序 key 数组，第二参数新增为隐藏 key 数组。

## 保存规则

浏览器保存项为 `table-column-order:<storageKey>`，值为列 key 的 JSON 数组。例如：

```json
["selection", "customer", "order-number", "date", "remark", "actions"]
```

- 财务列表：`table-column-order:sales-finance-list`。
- 物流列表：`table-column-order:sales-logistics-list`。
- 列宽使用已有的 `table-column-widths:` 前缀，互不覆盖。
- 显示开关使用 `table-column-hidden:<storageKey>`，值为隐藏列 key 的 JSON 数组，例如 `["phone", "address"]`；旧用户未保存此项时默认全部显示。
- 新增列追加到已有普通列之后；固定列始终按默认顺序放在两端。
- 暂时隐藏的列不会显示，其已保存位置在调整其它可见列时保留；旧版本未知 key 不生成空列。
- 无效 JSON、重复 key 或存储不可用时安全降级；保存失败仍可在当前页面正常使用排序和显示开关。
- 同一浏览器的同一 `storageKey` 共用偏好，不会同步到其它浏览器或设备。

## 接入边界与验证

- 推荐用于单行表头、每个数据行的普通列一一对应的表格。分组表头、任意合并单元格需要业务层单独处理。
- 低层 composable 的加载行、空态行应使用 `visibleColumns.length` 计算列数。统一指令会自动调整已有合并单元格。
- 合计行如果按字段展示金额，也应使用相同列定义渲染；不能保留按旧位置硬编码的合并区域。
- 弹窗中的拖动监听会在拖动结束、取消、失焦、关闭或组件卸载时清理。
- 统一指令已处理表头单击与双击的区分；自行接入低层 composable 的特殊表格仍需自行处理对应事件。
