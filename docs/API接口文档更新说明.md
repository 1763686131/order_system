# API接口文档更新说明

## 更新时间

## 更新概述
本次更新主要完善了订单管理相关的API接口文档，重点补充了新订单格式（销售单）的接口说明，并新增了运营商标签管理章节。

## 主要更新内容

### 1. 订单管理章节（第5章）全面重写

#### 1.1 获取订单列表接口 (5.1)
**更新内容**：
- 补充了**旧订单**的完整响应示例
- 新增了**新订单（销售单）**的完整响应示例
- 说明了新旧订单数据结构的差异

**关键字段说明**：
- `type`: 0=旧订单, 1=新订单（销售单）
- `order_goods`: 新订单的商品明细数组
- `order_number`: 新订单的订单编号
- `contact_person/contact_phone/contact_address`: 新订单的联系信息
- `project_name`: 新订单的工程项目名称
- `subtotal_amount/tax_amount/total_amount`: 新订单的财务信息
- `should_receive/current_payment/current_debt`: 新订单的收款信息

#### 1.2 获取单个订单详情接口 (5.2)
**新增内容**：
- 明确说明用于订单编辑功能
- 返回格式同订单列表，但返回单个订单对象

#### 1.3 创建订单接口 (5.3)
**更新内容**：
- 完整的新订单创建请求参数说明
- 包含商品明细数组 `items` 的结构
- 财务信息字段的完整说明
- 响应示例更新

**重要说明**：
- **库存不足时允许保存**，不阻止录入
- 自动计算各项财务金额
- 自动生成冗余字段（兼容旧格式）
- 保存成功后自动扣减库存

#### 1.4 更新订单接口 (5.4)
**新增内容**：
- 支持**完整订单更新**（编辑销售单）
- 支持**仅更新订单状态**
- 支持**仅更新物流信息**（含运费明细）
- 支持**更新为已发货状态**

**多种更新场景示例**：
```json
// 场景1：完整订单编辑
{
  "storeId": 1,
  "customerId": 5,
  "items": [...]
}

// 场景2：仅更新状态
{
  "status": "completed"
}

// 场景3：仅更新物流信息
{
  "logistics_no": "三志物流-SF123456",
  "audit_state": 1,
  "freight_costs": [...]
}

// 场景4：标记为已发货
{
  "status": "shipped",
  "shipping_method": 0,
  "shipped_date": "2026-09-02 14:00:00"
}
```

#### 1.5 删除订单接口 (5.5)
**更新内容**：
- 说明新订单删除时会**自动恢复库存**
- 说明旧订单删除不影响库存
- 建议已发货订单先撤销出库再删除

#### 1.6 上传回单图片接口 (5.6)
**更新内容**：
- 明确 Content-Type 为 multipart/form-data
- 参数名称为 `receipt_image`
- 返回上传后的图片URL

#### 1.7 删除回单图片接口 (5.7)
**更新内容**：
- 说明会从数据库和硬盘中**彻底删除**
- 不可恢复操作

#### 1.8 批量删除订单 (5.8)
**新增内容**：
- 说明前端通过并发调用实现
- 使用 Promise.allSettled() 确保所有请求完成

#### 1.9 更新订单已支付金额接口 (5.9)
**更新内容**：
- 用于物流对账功能
- 更新运费的已支付金额
- 记录更新时间和操作人

#### 6.1 获取运营商标签
- **接口**: `GET /api/carrier_tags`
- **说明**: 获取历史物流公司快捷标签
- **限制**: 最多返回20个标签

- **逻辑**: 
  - 新标签插入到列表开头
  - 去重处理
  - 最多保留20个

## 关键技术要点

### 新旧订单兼容性
- **数据结构**: 新订单包含 `order_goods` 数组，旧订单使用单一字段
- **字段冗余**: 新订单同时保存新旧两套字段，确保向后兼容
- **识别标识**: `type=1` 表示新订单，`type=0` 表示旧订单

### 库存管理逻辑
- **录入时**: 库存不足允许保存，不阻止录入
- **保存后**: 自动扣减库存
- **删除时**: 新订单删除会自动恢复库存

### 财务计算逻辑
后端自动计算：
- `subtotal_amount` = 所有商品的 amount 之和
- `tax_amount` = 所有商品的税额之和
- `total_amount` = 所有商品的 total_amount 之和
- `should_receive` = total_amount - discount_amount + other_fees
- `current_debt` = should_receive - current_payment

## 使用建议

### 前端开发
1. 通过 `type` 字段判断订单类型
2. 新订单优先读取 `order_goods` 数组
3. 旧订单回退到 `goods_name` 等单一字段
4. 搜索功能需同时支持新旧字段

### 接口调用
1. 创建订单使用 POST `/api/orders`
2. 编辑订单使用 PUT `/api/orders/<id>`
3. 仅更新状态或物流信息时，只传递需要更新的字段
4. 删除订单前检查是否已发货

### 物流管理
1. 使用运营商标签接口获取历史记录
2. 审核出库时保存物流公司名称会自动加入标签
3. 专车订单（shipping_method=3）不记录标签
