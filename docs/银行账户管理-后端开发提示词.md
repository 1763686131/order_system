# 银行账户管理 - 后端开发提示词

## 概述
为 `src/views/admin/finance/BankAccounts.vue` 组件提供完整的后端 API 支持，实现银行账户的增删改查、文件上传及系统配置管理。

## 一、数据库设计

### 1. 银行账户表 (bank_accounts)
需要包含以下字段：
- `id` - 主键
- `store_id` - 所属门店ID（外键关联门店表）
- `account_name` - 账户名称
- `account_number` - 银行账号
- `bank_name` - 开户行名称
- `bank_code` - 银行行号（可选）
- `balance` - 账户余额（数值类型，默认 0.00）
- `card_color` - 卡片背景颜色（十六进制色值，如 #1a1a1a）
- `card_bg_image` - 卡片背景图片路径（相对路径或完整 URL）
- `bank_icon` - 银行图标路径（相对路径或完整 URL）
- `created_at` - 创建时间
- `updated_at` - 更新时间

### 2. 系统配置表 (system_settings)
需要存储路径配置：
- `key` - 配置键名
- `value` - 配置值
- `description` - 配置说明

重点配置项：
- `bank_card_bg_path` - 银行卡背景图上传路径（默认：/app/uploads/bank-cards/backgrounds）
- `bank_icon_path` - 银行图标上传路径（默认：/app/uploads/bank-cards/icons）

## 二、API 接口设计

### 1. 银行账户管理接口

#### GET /api/bank-accounts
- 功能：获取银行账户列表
- 查询参数：`storeId`（可选，按门店筛选）
- 返回：账户列表，需关联查询门店名称（`storeName`）
- 注意：返回的图片路径需要是可访问的完整 URL 或相对路径

#### POST /api/bank-accounts
- 功能：创建银行账户
- 请求体：包含所有账户字段
- 验证：必填字段验证（storeId, accountName, accountNumber, bankName）
- 返回：新创建的账户信息

#### PUT /api/bank-accounts/:id
- 功能：更新银行账户
- 请求体：需更新的字段
- 验证：账户是否存在、权限验证
- 返回：更新后的账户信息

#### DELETE /api/bank-accounts/:id
- 功能：删除银行账户
- 验证：账户是否存在、是否可删除（检查是否有关联订单）
- 清理：删除账户关联的上传文件（背景图、图标）

### 2. 文件上传接口

#### POST /api/upload/bank-card-background
- 功能：上传银行卡背景图
- 接收：multipart/form-data 格式的图片文件
- 验证：文件类型（仅允许图片）、文件大小限制（建议 5MB 以内）
- 存储位置：从系统配置读取 `bank_card_bg_path`
- 返回：上传后的文件访问路径

#### POST /api/upload/bank-icon
- 功能：上传银行图标
- 接收：multipart/form-data 格式的图片文件
- 验证：文件类型（仅允许图片）、文件大小限制（建议 2MB 以内）
- 存储位置：从系统配置读取 `bank_icon_path`
- 返回：上传后的文件访问路径

### 3. 系统配置接口

#### GET /api/settings/paths
- 功能：获取所有路径配置
- 返回：包含 `reportPath`, `documentPath`, `receiptPath`, `bankCardBgPath`, `bankIconPath` 等配置
- **参考实现**：已有 `backend/routes/settings.py` 中的实现，需扩展添加银行卡路径字段

#### PUT /api/settings/paths
- 功能：更新路径配置
- 请求体：需要更新的配置项（包括新增的 `bankCardBgPath`, `bankIconPath`）
- 验证：路径格式验证、路径是否可写
- 返回：更新后的配置
- **参考实现**：可参考现有 `save_path_settings()` 方法，使用 `set_setting()` 保存新配置

#### POST /api/settings/paths/test
- 功能：测试路径是否可用
- 请求体：`{ path: "/app/uploads/..." }`
- 检查：目录是否存在、是否有读写权限
- 返回：测试结果信息
- **已实现**：`test_path()` 方法已存在，使用 `inspect_directory()` 进行检测

#### GET /api/settings/directories
- 功能：浏览服务器目录结构
- 查询参数：`path`（可选，不传则返回根目录列表）
- 返回：当前目录的子目录列表
- **已实现**：`browse_directories()` 方法已存在

## 三、关键业务逻辑

### 1. 文件上传处理
- 生成唯一文件名（避免冲突）：建议使用时间戳 + 随机字符串
- 保存文件到配置的目录
- 如果更新账户时上传了新图片，删除旧图片文件
- 返回的路径应该是相对于静态资源根目录的路径或完整 URL

### 2. 数据完整性
- 创建/更新账户时，验证 `storeId` 对应的门店是否存在
- 删除账户时，检查是否有关联的财务记录或订单
- 查询账户列表时，需要 JOIN 门店表获取 `storeName`
- 图片路径可以为空（使用默认样式）
- **余额计算**：账户余额应该根据收支记录动态计算或定期同步更新

### 3. 余额管理
- 账户余额字段用于卡片背面展示总金额
- 余额更新时机：
  - 收款时增加余额
  - 付款时减少余额
  - 财务调整时修改余额
- 建议提供余额重新计算接口，用于数据校验和修复
- 余额字段应该使用 DECIMAL 类型，避免浮点数精度问题

### 4. 权限控制
- 所有接口需要登录认证
- 根据用户角色控制操作权限（普通用户只能查看，管理员可以增删改）
- 门店用户只能管理自己门店的账户

### 5. 静态文件服务
- 配置静态文件服务，使上传的图片可以通过 HTTP 访问
- 路径映射：`/app/uploads/bank-cards/*` 应该可以通过 URL 访问
- 考虑添加图片访问权限控制（如需要）

### 6. 路径配置工具方法（参考现有实现）
- 使用 `get_setting(key, default)` 读取配置
- 使用 `set_setting(key, value)` 保存配置
- 使用 `inspect_directory(path)` 验证路径可用性
- 使用 `normalize_server_path(path)` 标准化路径格式
- 使用 `list_directories(path)` 浏览目录结构

## 五、注意事项

1. **路径配置灵活性**：系统配置的上传路径应该支持动态修改，使用 `get_setting()` 和 `set_setting()` 方法管理
2. **文件清理**：删除或更新账户时，记得清理不再使用的图片文件，避免垃圾文件堆积
3. **图片优化**：考虑对上传的图片进行压缩处理，减少存储空间
4. **默认值处理**：当图片路径为空时，前端会使用默认样式，后端返回空字符串或 null 即可
5. **错误处理**：所有接口需要统一的错误返回格式，包含 `success`, `message`, `data` 字段
6. **并发控制**：上传文件时考虑并发情况，避免文件名冲突
7. **备份策略**：重要的银行账户数据建议定期备份
8. **余额精度**：使用 DECIMAL 类型存储金额，保证精度（建议 DECIMAL(15, 2)）
9. **余额一致性**：提供余额校验和重算机制，确保余额与实际收支记录一致
10. **路径验证**：保存路径配置时使用 `inspect_directory()` 验证路径的可读写性
